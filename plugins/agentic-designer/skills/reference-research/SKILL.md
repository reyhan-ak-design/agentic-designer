# Reference Research (Mobbin)

## Budget
- Fast/Standard: max **2 searches**; Premium/Explore: max **4** (Mobbin + web for Dribbble/Behance/Awwwards). `limit` ≤ 12 each.
- The Manager's references in the brief come first and count as the hero reference when given. Prefer `mode: "standard"` unless the query is nuanced.
- Set `output_destination: "design_tool"`, `output_tool: "Figma"`, and a stable `task_intent`.
- If Mobbin is unavailable, write "No reference run" in the plan and rely on the Domain Pack patterns.

## Search by job, not by look
- Good: "bank transfer amount input with source account and balance", "back office transaction table with filters and bulk actions".
- Name a specific app only when the brief asks for parity with it.
- Aim for 5–8 references from ≥ 3 different apps, including mature regional (Indonesian/SEA) products when the platform has them.

## Extract decisions, not pixels — the pattern note
Write 3–6 lines in the plan:
```
REFERENCES (n apps): <app names>
Hero: <what is hero, approx size>        | median ≈ <value>
Type sizes on screen: <count>             | median ≈ <n>
Gaps: T1≈ T2≈ T3≈                         | median
Primary action: <placement / sticky?>
Hard cases: <keyboard-up handling, long names, errors>
Takeaway for our plan: <1–2 decisions you changed or confirmed>
```

## Floor and ceiling
- **Floor (median):** Mobbin patterns for usability — what users expect, where actions live, hard cases.
- **Ceiling (hero reference):** ONE best-in-class screen whose ambition we must match. Plus a mood board:
```
HERO REFERENCE: <link/file> — why it is excellent (1 line)
MOOD BOARD
| Ref | Take: typography | color | composition | imagery | motion |
|---|---|---|---|---|---|
| 1 | … | … | … | … | … |
| 2 | … |
| 3 | … |
OUR TWIST: <how we make it ownable for this brand>
```
Concept shots (Dribbble/Behance) give visual moves only — never structure, states, or data rules.

## Anti-copy rules
- Never reproduce a reference's composition, illustration, or brand styling one-to-one.
- Always re-express the pattern with the client's DS components and tokens.
- If the final frame is recognizable as a specific app at a glance, it fails.
- References are evidence, not authority: a decision must still serve the objective.
