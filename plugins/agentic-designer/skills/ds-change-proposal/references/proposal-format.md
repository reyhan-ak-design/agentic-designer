# DS Change Proposal format

```
DS CHANGE PROPOSAL — <title> — Desi — <date>
Type: color | number | typography | semantic token | component
Source: Jarvis review <link> | designer DS gap | Desi audit

PROBLEM: <what is wrong or missing, in one paragraph>
EVIDENCE: <screens/components/nodes affected, measured values, rule IDs>

OPTIONS
A. <change> — pros / cons
B. <change> — pros / cons
(C.)
RECOMMENDATION: <option + one-line reason>

EXACT CHANGE (for the recommended option)
- <collection / variable or style or component> : <before> → <after>

IMPACT
- Brand modes: <per mode: none | changes + contrast result>
- Light/Dark: <result>
- Components consuming it: <list / count>
- Known screens: <list>
MIGRATION: <none | steps>
RISK: <low/med/high + why>

DECISION (Manager): approve A/B/C | reject — <reason>
```
